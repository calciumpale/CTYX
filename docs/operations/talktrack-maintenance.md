# Daily talk-track maintenance

The existing Site must remain owner-private. POST /api/talktracks/maintenance through the Sites-supported service access. Service access is obtained from a fresh get_site response, sent only to this Site in the OAI-Sites-Authorization header, and never stored in source or task prompts. The gateway authorizes unattended callers; no visitor identity is invented. A signed-in visitor can maintain only their own workspace and must use the manager view. If the audience changes, add separate service authorization before enabling this endpoint.

The endpoint accepts no user identifiers, transcripts or credentials. It checks only workspaces whose policy has been explicitly enabled by a manager. Default policy is disabled. Count distinct manually entered projects that used the script and subsequently closed; require at least 10 closed projects, configured low win rate, and configured idle days. Correlation is not causal attribution. Downweight once to 0.5 or archive reversibly; never delete. Manager review can restore archived records. The response exposes only workspace and update counts. Repeated calls are safe; revision conflicts reload and retry up to three times. Failure must not be reported as a successful maintenance run.

Scheduled tasks call the updater and read back its JSON counters; they do not republish the Site. Notify only on failed access, failed updates, or meaningful changes. The daily dispatcher is separate from the per-project feedback pipeline, which is triggered by confirmed wins/transcript submission and has explicit retry controls for missing model/Embedding configuration.

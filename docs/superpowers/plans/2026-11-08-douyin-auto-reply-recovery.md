# 抖音普通咨询自动回复修复

> **For agentic workers:** Use test-driven implementation and independent review before publication.

**Goal:** 普通面积咨询由 AI 自行接待，技术同步故障恢复后继续处理未回答来信，不因默认夜间时段或误转人工长期停住。

**Evidence:** 现场会话已经同步“80–100 平空铺还有吗”，但处于 human 模式，原因为“会话同步暂时失败”。源码确认人控状态永久保留、人工 wait 会消耗待答来信、首次不可靠读取的普通消息无法恢复资格、默认 08:30–21:30 拦截凌晨模型调用；模型调用链本身已正确接入。

## Changes and verification

1. `prospecting-chat-store.ts` / SQLite tests：技术暂停保留自动模式，可靠身份一致的快照恢复后继续；只恢复明确技术原因的旧人控状态，重放范围限于最后确认外发后的最新待答来信。显式人工、业务转交、客户拒绝和未知发送继续保留原约束。
2. 使用单独资格标记记录首次不可靠的当前自动来信；可靠重读后仅提升该类消息一次，不提升历史或仅观察导入的消息。
3. `prospecting-chat-policy.ts` / types / UI：增加可选 replyHoursEnabled；默认全天回复客户来信，用户可明确限定时段。旧默认时段不再隐式禁用夜间；旧自定义时段继续保留。
4. `prospecting-chat-agent.ts` / tests：普通面积、区域、预算等问题资料不足时澄清需求；有依据的事实可附一条需求问题。不得编造房源余量、面积、价格；客户要求人工、商务风险和资料冲突仍转人工。
5. `bridge-core.mjs` / tests：仅尚未 dispatch 的 ACCOUNT_VERIFICATION_PENDING 回复失败附带可重试标记；未知或已经开始发送的结果绝不自动重发。
6. 完整浏览器测试、类型检查、生产构建与 Excel 检查，独立复查后发布现有 Site、同步私有 GitHub，并安全更新本机助手。现场观察实际待答会话的恢复、生成、排队和发出。

## Boundaries

- 账号、租户、快照、租约、持久发送日志和既有发信额度不放宽。
- 保留人工接管、草稿、中文输入法和 36/44px 控件规范；不使用左侧彩色强调条。
- 软件测试使用隔离页面与合成消息，不向客户发送测试文本。现场只允许已有真实会话按用户已开启的 AI 接待流程继续。

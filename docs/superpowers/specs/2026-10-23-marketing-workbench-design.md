# CTAI 营销多智能体工作台：实施规格

## 交付
可本地运行、可私有发布的完整全栈试点。遵循 PRODUCT.md 与 DESIGN.md。企业 CRM、SSO、真实模型通过后续企业授权接入，不把体验空间视为生产企业权限。

## 页面
1. 销售首页：个性化问候、任务建议、带上下文的输入框、五专家入口、最近商机。管理首页：经营概况、漏斗、优先介入商机、Skill 待审。
2. 商机：阶段筛选、搜索、详情抽屉、备注、带确认的阶段推进、CSV 导出。
3. 培训：选择剧本，逐轮客户扮演，结束后展示带依据的规则演示评分与改进建议，结果持久化。
4. 知识与技能：知识检索和 Markdown / 文本导入，候选/生效/退回列表，经理审核并记录版本与原因。只有生效知识供建议引用。
5. 搭建中心：允许节点类型的可视化工作流、选择节点配置、增删/移动、保存草稿、拓扑验证、测试运行与管理者发布；不运行任意代码。
6. 运行记录：真实请求轨迹、输入输出、引用、路由、耗时；无外部模型时明确演示。

## 数据和服务
每个经平台认证的用户拥有独立 D1 workspace；state JSON 与 revision 持久化，使用乐观并发防覆盖。体验身份保存在服务端 HttpOnly cookie，服务端按身份过滤样例客户并限制管理动作；切换身份不能触达其他平台用户数据。服务端执行发布、审核、数据修改；前端不能直接修改数据库或持有模型密钥。

所有动作统一 POST /api/workbench，客户端通过 app/lib/api.ts 封装。GET 同一路径取得 WorkbenchState。详见 app/lib/types.ts。

## 质量
必须验证服务端角色限制、候选引用隔离、陈旧版本冲突、工作流循环/无出口、客户越权和持久化。UI 验证桌面/移动、浅深主题、导航、中文输入、聊天、审核发布和搭建保存。无真实数据与模型时仍能用明确标识的样例完成端到端闭环。

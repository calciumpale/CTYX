# 抖音评论获客

按用户指定的四步流程在现有工作台新增业务入口：输入产品与目标客群要求、发现真实竞品账号、选择账号采集公开评论、人工审核后自动打招呼。人工审核默认开启，创建任务时可显式切换自动模式。沿用暖白纸面与 CDS tokens，无装饰性的左侧色条。

## 方案与边界

沿用云端 D1 业务队列与本地桥接架构。浏览器登录态只保存在本机。用户的执行请求已授权实现此流程，具体技术选型由本次实现负责。云端不能直接运行 Playwright，因此本地执行器通过带设备凭证的接口拉取任务。管理员不能读取线索正文；业务账号只管理自己的获客任务。

研究 MediaCrawler 的搜索、指定视频采集和 JSONL 导出模式。当前源码对作者匿名化，且采用非商业学习许可，因此不复制、反匿名化或捆绑其代码。提供现有导出的分析导入；匿名作者不可发信。完整流程使用独立的浏览器公开页面适配器。另一候选 douyin-cli 的私信 ACK 和重试实现不足以证明提交成功，故不将其 `sent` 作为可靠回执。

## 功能

- 产品要求生成可编辑搜索词，实际浏览器搜索返回带来源视频的账号，不生成虚构账号。
- 按所选账号已发现的视频限量采集，保留评论原文和来源链接；结果为空如实显示。
- 模型对评论评分并生成招呼草稿。无模型时规则初筛、可人工审核，禁止规则结果触发自动发送。
- 审核绑定评论版本与最终文案；批准即入队。自动模式只接纳达到阈值且有可联系公开身份的模型结果。
- 暂停任务取消待发送项；已进入发送的请求不会被宣称撤回。首次触达按发送账号与目标账号去重，发送间隔与每日上限在服务器控制。
- 私信结果分为已提交、失败和待核对；浏览器里观察到发送动作及新消息只证明提交，不证明送达或已读。未知状态不可自动重发。
- 设备配对、在线/登录状态、任务记录、连接说明均在功能内可见；没有连接时可以保存需求，不能伪造采集或发信成功。

## 验证

使用真实 SQLite 验证租户/成员隔离、审核版本冲突、去重、暂停与设备停用、租约过期不重复发信。执行器测试参数校验、本地日志重放、超时未知与结果上报重试。运行全量测试、类型检查、构建并检查桌面/移动界面。没有已登录抖音及具体营销内容时，不用真实陌生人做发送测试。

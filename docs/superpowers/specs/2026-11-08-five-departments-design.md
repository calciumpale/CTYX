# 五科室 AI 营销工作台

日期：2026-11-08。范围来自用户本轮六项要求；医院限定嘉兴，其他行业优先嘉兴及周边，餐饮品牌可全国。图片、视频后续使用用户提供的 APIMart 密钥。

## 交付与实现选择

在现有 React / TypeScript / Vinext、D1、R2 工作台内扩展，沿用现有中性灰界面、权限和模型连接。保留现有站点访问范围与 GitHub 私有仓库，产品名统一为“AI营销工作台”。新增功能完成后同步源码、测试、发布；账号及公开企业资料导入为显式、幂等的一次性管理操作。

素材入口放在“社交平台获客”下方、“项目跟进”上方，名称“AI营销素材生成”。内部依次为产品介绍 PPT、提示词图片、提示词视频，以编辑区、结果预览、历史任务组成工作面。保留已授权业务功能与发送保护。

五个账号密码均按用户指定设为 admin；登录支持大小写。原 sales 改名为 ZS，保留 account_id、sales-1 与设备、任务、会话、记忆、发送记录的引用。已有原 sales 业务归属 ZS；其余四个账号独立 salesId。管理员、管理者账号和密码保持原样。

同时改掉服务端按 sales-1 写死的读取、写入、合同、审批、录音、转写、训练和模型上下文权限，使用本次鉴权得到的成员 salesId。销售不得读写其他账号的企业、项目、历史或媒体；管理员不因此取得客户项目权限。管理者可按授权查看和分配。

账号迁移与凭据初始化只执行一次，使用随机盐和既有 PBKDF2 密码散列，重试不重置后续修改的密码。迁移前保存可恢复快照；全批次通过工作空间版本 CAS，冲突不覆盖新数据。

执行前检测同名账号、重复 salesId、旧账号意外状态和既有迁移记录；冲突返回明确清单，不覆盖另一个成员。每条账号、备份、迁移记录及工作空间语句都携带相同的预期工作空间及账号状态守卫，不能只在最后检查 CAS。保留原审批身份别名，避免 sales 改名后丢失原本分配给该身份的审批。新空间初始化五账号，旧空间不因登录重建 sales 或反复改密码。工作空间仍受现有 180 万 UTF-8 字节上限约束，导入前计算容量并留出余量。

## 2. 真实企业与旧企业替换

每类目标约 50 家，优先使用政府公示、许可名单、行业协会或机构官网。每条至少保留真实机构全称、类别、已核实地区、来源链接、来源标题、资料日期与核验时间；地址、官网、公开业务电话只有来源支持才填写。医院不把科室、规划新建机构或同一实体的重复名称凑成家数；旅行社分公司显式标明。

以独立的公开线索来源导入各账号企业目录，标为待开发，金额为 0，不编造联系人、采购需求、客户预算、沟通记录或成交概率。资料与用户确认的客户事实分开；导入不能制造 250 条真实销售活动。名称、统一信用代码及地区去重；保留每条来源，汇报实际有效数量。

旧企业退出当前企业目录。未改动且没有引用的示例可移除；有真实项目、笔记、合同、录音或运行历史的旧记录转入归档并保留历史链接，历史业务归 ZS。此处采用可恢复的替换方式，避免“不要旧企业”造成历史证据连带丢失。其他知识、话术、工作流与社交获客任务不清空。

## 3. AI 营销素材生成

PPT 使用现有文字模型整理产品介绍内容：产品名称、目标客户、卖点、应用场景与补充资料；生成结构化页稿，允许修改和预览后导出可编辑 .pptx。无来源的业绩、客户、价格或医疗效果不得补写为事实。缺少文字模型时保留输入并提示配置。

图片与视频使用 APIMart 官方 API。管理员在“服务连接”保存一份加密密钥及可选模型配置；普通销售只见可用状态，密钥不进入浏览器、日志、任务返回或导出文件。密钥稍后由用户填写，本轮完成接口、界面、任务状态与模拟契约验证，不冒充已完成付费生成。

图片支持提示词、横竖比例与张数（默认 1）；视频支持提示词、比例和官方模型支持的短时长。提交后保存任务 ID 与状态，页面刷新后继续查询原任务，明确显示等待、生成中、成功、失败和结果待核对。网络超时后不自动重提计费请求；重复点击由幂等键拦截。成功结果可预览并下载，结果读取始终校验账号权限。提供失败恢复和保留草稿。

调用生成服务前先持久化本账号任务和请求指纹；同一幂等键的不同内容返回冲突，跨账号键不相互暴露。提交超时或未能保存任务 ID 时记录结果待核对，不自动创建第二笔计费任务。状态查询限频并按版本合并，旧响应不能覆盖终态。下载后的生成结果保存到私有 R2，预览/下载通过有权限的应用接口读取；来源 URL 只供服务端受限取回，不进入销售任务列表。结果待保存、链接过期与生成失败分开处理。用户未提供密钥之前用固定合成响应验证协议，不调用付费生成。

APIMart 图片和视频采用各自官方端点和异步任务协议，不拿文字 Chat Completions 冒充媒体生成。默认使用已核实可用模型的保守参数；模型和参数依官方契约校验。没有密钥时不发生成请求。

## 4. 回复机器人恢复

现有助手仍在轮询。线上消息读取从 17:13 的图片/表情消息起持续判为不可靠，整段历史因一条非文字消息永久阻塞。修复必须先用隔离浏览器回归复现。

在作者、方向、目标和排序已经核实的前提下保留带类型的非文字消息占位；不猜图片内容、不从占位提取客户事实。最新非文字消息使用明确的文字说明请求，后续文字仍正常进入任务记忆和知识库回答。未知作者、混合内容歧义、未提交发送、身份不明及历史覆盖缺口仍暂停核验，不通过取消安全检查恢复发送。保留任务暂停、人工接管、停联、unknown 外发和邀请预算。

先修复并验证机器人，可独立于新增功能发布。线上验证只用只读诊断和现有运行观察，不向真实客户发送测试消息。

## 5. 关键词全网线索采集

在现有获客区增加“全网线索”模式，输入产品/目标、关键词与地区，可选全网、贴吧、小红书及其他公开网站。以搜索引擎公开索引为第一版，平台选择由服务端固定域名约束；贴吧必须填写地区，查询和结果保留地区依据。不把未证实地区显示为已匹配。

收集结果保存标题、原文摘要、公开作者（可得时）、平台、来源 URL、关键词、地区匹配状态、发布时间（可得时）、采集时间与人工处理状态。按账号独立存储并去重；支持查看原文、筛选、标记有效/忽略，以及明确选择后转入项目。网页线索不是已核实客户意向，模型不能编造帖子、电话或出处。

本轮不增加贴吧/小红书私信或回复，不复用抖音发送队列。无结果、来源超时、登录限制和搜索失败分别显示；不将失败当作成功空列表。公开索引未覆盖的登录内内容不宣称已采集；如以后接入已授权平台 API，可复用同一线索存储和审核流程。

第一版复用现有公开检索所采用的 Bing RSS 固定 HTTPS 搜索端点。每个任务最多 5 个关键词、40 字/词，单次最多合并 50 条，单查询超时 8 秒、整次有界执行，账号同一时刻最多一个采集任务并限制重复触发。平台选择只允许登记的平台域名；返回 URL 再核对域名而不只依靠 site 查询。贴吧记录保留地区原文证据，不明确匹配的结果放待核实而不假定属地。所有来源正文作为不可信资料，不改变系统指令或账号权限。

## 验收

五账号登录与双向隔离、原 sales 连续性、迁移重试/冲突及恢复、各类来源及去重数量、无虚构销售证据；PPTX 可打开和编辑；APIMart 官方协议、任务幂等、跨账号结果拒绝与缺少密钥状态；全网搜索的地区/平台约束、真实来源和失败状态；图片消息阻塞回归、文字恢复与原发送门禁；桌面/移动端入口、固定布局和历史草稿。

最后执行全量回归、类型检查、lint、token、diff、生产构建及独立审查，再同步 GitHub 与现有 Site。保持旧 v1.2.1 标签和现有访问范围。实际 APIMart 生成需用户稍后填入密钥后验证，发布结果明确说明这一边界。

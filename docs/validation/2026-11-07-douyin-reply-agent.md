# 抖音回复 Agent

本轮沿用现有获客任务、抖音助手、会话同步、留资池和人工接管；不另建采集或发送通道。

## 配置与行为

在「社交平台获客」的当前任务会话中打开 AI 回复设置，选择允许向客户引用的知识库，并设置自动回复额度与时段。新上传的文档默认不参与客户回复；空选择不会检索全部文档。原有已发布、非示例的资料和话术继续参与检索。

自动回复默认北京时间08:30至21:30，每发信账号每日30条、每会话滚动24小时12条。每日打招呼额度单独计算，原有60秒发送间隔保留。配置额度是自动回复的上限；人工回复是明确操作，可在时段外发送，并计入当日回复统计。未处理的客户来信在时段或额度恢复后继续处理，仍需要本机助手在线、账号确认和可靠会话快照。

客户明确提供的面积、业态、预算、区域、入驻时间、看场意愿会保存在会话需求中。已留资不重复索取联系方式，拒绝提供联系方式两次后停止索取。看场意愿和时间是待确认需求，不代表已成功预约。

明确要求停止联系时，会话关闭并保存原因，同一工作空间、发信账号和客户在后续任务中也不得再次触达。投诉、隐私、合同或商务承诺转人工。结果不明的发送不自动重试。客户联系方式仍只在授权的会话和留资池中查看，模型与检索输入做脱敏。

## 验证

使用合成来信、内存SQLite和隔离的本地浏览器夹具验证。测试不会打开真实客户会话或发送真实私信。PROSPECT_BROWSER_TEST=1 npm test：920/920通过，无失败、无跳过。TypeScript检查、变更文件ESLint、CDS设计变量检查和git diff --check通过。隔离桌面/移动浏览器验证了未保存设置保留、失败重试、任务切换、草稿、自动滚动、关闭会话保护及36/44px控件高度。独立代码审查完成，发现的问题均已回归验证。


## 实施取舍

- 保留现有TypeScript/D1与本机助手收发链路，没有采用需求草稿中另建Python机器人和三种通道的方案；后续若切换官方接口，需要另行验证账号权限。
- 自动回复按时段与额度排队；人工回复作为明确操作可在时段外发送，明确拒收后两种方式都禁止。
- 新文档须选择允许引用的知识库；原有已发布、非示例的资料与话术沿用，限制范围仅针对新增文档库。
- 策略发生实质变更时，受影响的待发或执行中AI回复转人工核对，避免旧资料外发；这会增加一次人工处理，完全相同的策略保存不会打断队列。
- 沿用现有验证码/账号异常暂停和未知发送结果人工核对；本轮没有新增账号级连续失败熔断器。
- 未验证真实客户首响时延；它仍取决于助手在线、账号状态、可靠同步和平台响应。本轮未向真实客户发送测试消息。

入口：社交平台获客 → 留资对接 → 客户会话 → 跟进设置。

# 跨客户发送预核验

## 复查发现

v1.2.1 的发送预核验复用了被动收信核验的全局五分钟冷却。前一位客户完成核验后，即使后一位客户的任务已经通过服务端一分钟发送间隔，发送仍可能在实际核验目标前被 `RECIPIENT_UNVERIFIED` 拒绝。刚完成一次健康读取也可能误挡已获批准的回复。

## 修复边界

发送预核验继续复用经过页面、上下文、目标、可见头部、同一元素与时效检查的缓存。未命中缓存时，主动发送必须实际核验目标，但不再受被动收信预算拦截。服务端按账号、任务开始时间、租约及策略限制发送；发送前的独立账号、目标、消息快照、草稿和持久化检查保持有效。错误目标在填写草稿前被拒绝。

被动收信的五分钟健康核验及新快照一分钟冷却保持有效。最终发送仍独立核验当前收件人；结果未知不会自动重发。

## 验证

新增八项隔离浏览器回归，旧实现六项失败、两项通过；修复后八项通过。覆盖 send/reply 的跨客户连续发送、刚完成前一客户健康核验的发送、同目标缓存与最终独立核验，以及错误新目标不填写、不提交。

完整带浏览器测试 1094 项通过，零失败、零跳过。类型检查、72 文件设计 token 检查和 diff 检查通过；lint 零错误、四处原有未使用变量警告。四处测试文件变量声明错误已清理。独立代码审查未发现新增阻断项。

测试页面拦截全部浏览器请求。现场日志最后一次可靠同步为北京时间 11:24:00，读取并上报 12 条消息；11:24:43 出现目标核验失败，11:24:53 助手停止。该现场错误可能来自读取冷却，不能仅凭错误文本归因于本次跨客户发送缺陷。实时客户收发需助手在线后另行核验。
